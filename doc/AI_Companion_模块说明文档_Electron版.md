# AI Companion — 模块说明文档

> 本文档用于说明 AI Companion 的产品定位、业务边界、模块职责、模块依赖和关键业务闭环。  
> 本文档面向产品设计、前端开发、桌面端开发、后端开发、测试和后续维护人员。  
> 本文档只描述“系统需要提供什么能力”以及“能力之间如何协作”，不描述具体类、函数、接口路径或实现代码。

---

## 1. 文档定位

AI Companion 是一个面向 Windows 和 macOS 的本地优先桌面 AI 产品。

本文件主要解决以下问题：

1. 明确产品到底解决什么问题。
2. 明确首个可用版本应包含哪些能力。
3. 明确桌面端、前端、本地服务和数据层的职责边界。
4. 明确各业务模块的输入、输出和依赖关系。
5. 明确隐私、安全和跨平台适配要求。
6. 为后续需求拆解、任务分配和验收提供统一依据。

本文件不是页面原型文档、数据库设计文档、接口文档或具体技术实现文档。后续开发可以在本文件基础上继续拆分产品需求、交互设计、接口协议和数据模型。

## 2. 产品定位

### 2.1 产品定义

AI Companion 是一款本地优先的个人 AI 桌面助手。

系统在用户明确授权和隐私规则约束下，保存用户的对话、桌面活动、长期记忆、用户修订和目标任务，并利用这些信息为用户提供持续、个性化且可追溯的 AI 对话体验。

产品核心不是单次问答，而是建立以下长期闭环：

用户产生对话或活动记录  
→ 系统识别其中可能长期有价值的信息  
→ 生成候选记忆  
→ 用户确认、纠正、否定或删除  
→ 系统在后续对话中检索相关记忆  
→ AI 基于最小必要上下文继续服务用户  
→ 对话结果进一步沉淀为目标和任务

### 2.2 产品解决的问题

普通 AI 聊天工具通常存在以下问题：

- 不同会话之间缺少连续性。
- 用户需要反复解释自己的背景、偏好和当前项目。
- AI 记住了什么、为什么记住、是否准确，用户无法控制。
- 对话内容难以沉淀为可执行的目标和任务。
- 桌面活动、对话和个人数据分散在不同位置。
- 长期使用后，用户无法有效审查、导出或删除自己的上下文数据。

AI Companion 通过本地数据管理、长期记忆、上下文检索和行动管理解决上述问题。

### 2.3 产品边界

AI Companion 当前定位为“个人上下文与长期记忆型 AI 助手”，而不是以下产品：

- 不是单纯的大模型聊天套壳。
- 不是员工监控或考勤系统。
- 不是默认记录全部键盘输入的输入监控工具。
- 不是自动控制所有桌面软件的通用智能体。
- 不是完全自主执行高风险操作的自动化系统。
- 不是默认将全部本地数据上传到云端的数据平台。
- 不是以团队协作和多人权限为核心的企业系统。

### 2.4 核心产品价值

产品价值由四个部分组成：

| 核心价值 | 说明 |
|---|---|
| 持续理解 | AI 能够基于用户过去确认过的信息保持长期连续性 |
| 用户可控 | 用户能够查看、确认、纠正、否定和删除系统记忆 |
| 本地优先 | 对话、活动、记忆、画像和任务优先存储在本地 |
| 可追溯 | 重要记忆和画像需要保留来源、状态和修订关系 |

## 3. 产品设计原则

### 3.1 用户授权优先

任何桌面活动采集、权限申请、模型调用和外部操作都必须以用户授权为前提。

系统不得通过默认开启、隐藏开关或模糊说明绕过用户授权。

### 3.2 隐私阻断优先

敏感场景应在采集发生前被阻断，而不是先采集、后判断。

当系统无法确认当前场景是否安全时，应优先停止采集或减少采集内容。

### 3.3 本地事实优先

对话、活动、记忆、画像、目标、任务和审计数据以本地数据库为事实来源。

前端状态、缓存、搜索索引和向量索引都不是独立事实源。

### 3.4 模型输出只作为候选

大模型生成的记忆、画像、分类和结构化结果均属于候选结果。

候选结果需要经过格式校验、业务规则校验和必要的用户确认，不能直接替代用户事实。

### 3.5 最小必要上下文

向外部模型发送数据时，只发送完成当前任务所需的最少信息。

系统不应为了“可能有用”而上传全部历史对话、活动记录或完整用户画像。

### 3.6 用户修订优先

用户主动确认、纠正、否定或删除的结果优先于系统自动推断。

自动任务不得覆盖用户已经明确修订的内容。

### 3.7 跨平台能力分级

Windows 和 macOS 的系统权限、活动采集和可用能力不同。

系统必须区分：

- 当前平台支持并已授权。
- 当前平台支持但尚未授权。
- 当前平台受限制。
- 当前平台不支持。
- 当前能力暂未实现。

不得将“未授权”“未实现”和“无数据”混为同一状态。

## 4. 总体架构

### 4.1 架构组成

系统由四个主要部分组成：

| 组成部分 | 职责 |
|---|---|
| Electron 桌面运行时 | 管理应用生命周期、窗口、托盘、权限、系统能力、本地服务和安全通信 |
| Vue 前端界面 | 提供对话、记忆、活动、目标、设置和数据管理等用户入口 |
| Python 本地服务 | 承担业务流程、模型调用、记忆处理、检索、任务调度和数据治理 |
| SQLite 本地数据层 | 保存业务事实、全文索引、向量索引（SQLite BLOB + NumPy）、任务状态和审计信息 |

外部模型服务只接收经过业务层筛选后的最小必要上下文。

### 4.2 依赖方向

系统依赖关系遵循以下方向：

用户界面  
→ 前端状态与请求层  
→ Electron 安全通信层  
→ 本地业务服务  
→ 业务模块与通用能力  
→ 本地数据库、索引和外部模型

上层可以调用下层能力，下层不能反向依赖具体页面。

### 4.3 核心边界

#### 前端界面边界

前端负责展示和交互，不负责：

- 直接读写数据库。
- 保存最终业务事实。
- 直接持有模型密钥。
- 直接管理 Python 进程。
- 直接调用操作系统高权限能力。
- 在页面中实现记忆提取和检索排序规则。

#### Electron 运行时边界

Electron 主进程负责桌面运行和系统边界，不负责：

- 记忆内容判断。
- 用户画像推断。
- 提示词业务编排。
- 目标任务业务规则。
- 数据库领域事务。
- 具体模型供应商业务逻辑。

#### Python 本地服务边界

Python 本地服务负责业务逻辑，不负责：

- 创建和控制桌面窗口。
- 直接管理前端页面。
- 绕过 Electron 申请系统权限。
- 绕过平台隐私设置采集数据。
- 保存明文密钥到普通配置文件。

#### 数据层边界

数据层负责持久化和索引，不负责：

- 决定业务流程。
- 生成用户画像。
- 生成 AI 回复。
- 处理页面状态。
- 判断是否应该采集某个桌面场景。

## 5. 技术栈约束

### 5.1 桌面端

桌面应用使用 Electron 构建，目标平台包括：

- Windows x64。
- macOS Apple Silicon。
- macOS Intel。

Electron 主进程负责窗口、托盘、开机启动、本地服务管理、权限检测、安全通信、凭据保护和应用更新。

### 5.2 前端

前端统一采用以下方案：

| 分类 | 规范 |
|---|---|
| 框架 | Vue 3 |
| 编写方式 | Composition API 与 `<script setup>` |
| 语言 | TypeScript |
| 状态管理 | Pinia |
| 路由 | Vue Router |
| HTTP 请求 | Axios，并使用统一请求封装和拦截器 |
| 样式 | Tailwind CSS v4 |
| UI 组件 | 自定义 Vue 组件 |
| 图标 | FontAwesome 6 |
| 表单校验 | 自定义校验或 VeeValidate |
| 页面加载 | 路由组件统一懒加载 |

禁止使用 Element Plus 和其他未经统一批准的组件库。

### 5.3 前端数据规范

前端与后端交互遵循以下规范：

- 请求参数和请求体使用 snake_case。
- 后端统一返回 code、message、data 三部分。
- code 等于 0 表示业务成功。
- 前端 API 层负责统一处理错误、鉴权状态和响应解析。
- 页面组件内部可以使用 camelCase，但不得直接改变后端协议。
- 页面必须分别处理加载、空数据、业务错误、权限错误和系统错误。
- 路由页面使用懒加载。
- 页面模板优先使用语义化标签。
- 模板层级应保持清晰，避免过深嵌套。

### 5.4 本地服务

本地业务服务使用 Python 和 FastAPI，承担：

- 本地业务接口。
- 对话流程编排。
- 记忆提取和校验。
- 用户画像和行为分析。
- 混合检索。
- 模型供应商适配。
- 后台任务和调度。
- 数据治理。

### 5.5 数据与索引

系统使用 SQLite 作为本地事实存储，并提供：

- 关系数据存储。
- 全文检索。
- 向量检索（嵌入向量以 BLOB 存入记忆行，FastEmbed + ONNX 本地推理，NumPy 余弦相似度检索）。
- 事务控制。
- 外键约束。
- 数据迁移。
- 备份与恢复。
- 数据加密能力。

向量索引和全文索引属于可重建的派生结构，不作为最终事实源。

## 7. 桌面运行与生命周期模块

### 7.1 定位

该模块是桌面应用的运行底座，负责 Electron 应用和 Python 本地服务的启动、运行、恢复和退出。

### 7.2 核心能力

- 管理应用单实例运行。
- 创建和恢复主窗口。
- 管理系统托盘。
- 管理开机启动设置。
- 启动和停止本地服务。
- 检查本地服务健康状态。
- 在本地服务异常退出时提供恢复机制。
- 管理应用正常退出和强制退出。
- 管理桌面应用版本和更新状态。
- 在数据库恢复等维护场景进入受控停服状态。

### 7.3 输入

- 用户启动或退出操作。
- 操作系统生命周期事件。
- 本地服务运行状态。
- 更新和维护请求。

### 7.4 输出

- 应用运行状态。
- 本地服务可用状态。
- 托盘和窗口状态。
- 更新状态。
- 维护状态。

### 7.5 设计边界

该模块只管理运行状态，不承担对话、记忆、画像和检索业务。

## 8. 安全通信与访问控制模块

### 8.1 定位

该模块负责隔离前端渲染环境、本地桌面能力和 Python 本地服务，避免页面直接获得高权限能力。

### 8.2 核心能力

- 为前端提供经过白名单控制的桌面能力。
- 将页面请求转发到本地服务。
- 转发对话等流式结果（通过独立 IPC 通道逐 token 推送，Renderer 通过回调接收，不接触完整密钥）。
- 隐藏本地服务端口和认证信息。
- 验证请求来源、参数和允许访问的能力。
- 对高风险操作增加确认和权限检查。
- 阻止页面直接访问文件系统、进程和系统凭据。
- 在浏览器调试模式和桌面正式模式下保持一致的业务接口。

### 8.3 输入

- 前端业务请求。
- 本地服务响应。
- 本地服务流式事件。
- 系统权限状态。

### 8.4 输出

- 标准业务响应。
- 流式对话事件。
- 权限错误。
- 运行时错误。

### 8.5 设计边界

该模块不解释业务内容，只控制访问路径、请求范围和通信安全。

## 9. 跨平台系统适配模块

### 9.1 定位

该模块统一 Windows 和 macOS 的系统能力差异，为上层提供一致的平台能力状态。

### 9.2 核心能力

- 获取当前前台应用。
- 在允许的情况下获取窗口标题。
- 获取用户空闲状态。
- 管理系统托盘。
- 管理开机启动。
- 管理系统通知。
- 检测和申请必要权限。
- 安全保存模型密钥和数据库密钥。
- 提供平台能力支持状态。
- 对不支持或未授权能力提供降级方案。

### 9.3 权限分类

系统需要独立管理以下权限：

- 活动采集权限。
- 辅助功能权限。
- 输入监控权限。
- 屏幕录制权限。
- 通知权限。
- 自动化权限。

不同能力不得共用一个笼统的“系统权限”状态。

### 9.4 跨平台状态

每项能力至少需要区分：

| 状态 | 含义 |
|---|---|
| 可用 | 平台支持且已授权 |
| 待授权 | 平台支持但用户尚未授权 |
| 已拒绝 | 用户明确拒绝 |
| 受限制 | 受系统策略或企业策略限制 |
| 不支持 | 当前平台无法提供 |
| 未实现 | 产品暂未接入该能力 |

### 9.5 设计边界

该模块只提供平台事实，不决定业务是否生成记忆或画像。

## 10. 前端应用框架模块

### 10.1 定位

该模块为所有用户页面提供统一的布局、导航、组件、状态管理、错误处理和交互规范。

### 10.2 核心能力

- 管理全局布局和导航。
- 管理页面路由。
- 管理跨页面状态。
- 提供统一请求层。
- 提供统一加载状态。
- 提供统一空状态。
- 提供统一错误展示。
- 提供统一确认交互。
- 提供统一表单组件。
- 提供统一弹窗、通知和反馈方式。
- 提供统一主题和视觉变量。
- 提供跨平台窗口尺寸适配。

### 10.3 页面模块

首版前端包含：

- 今日概览。
- AI 对话。
- 活动记录。
- 长期记忆。
- 用户理解。
- 目标任务。
- 模型设置。
- 隐私设置。
- 数据管理。
- 系统状态。

### 10.4 组件规范

前端组件分为：

| 类型 | 说明 |
|---|---|
| 基础组件 | 按钮、输入框、卡片、弹窗、状态提示等通用组件 |
| 应用组件 | 导航栏、侧边栏、窗口栏、全局通知等应用级组件 |
| 业务组件 | 记忆卡片、活动条目、消息气泡、目标卡片等跨页面业务组件 |
| 页面私有组件 | 只服务于单个页面的局部组件 |

所有组件使用 Vue 3 Composition API、自定义组件和 Tailwind CSS 构建。

### 10.5 设计边界

前端状态用于交互和缓存，不得替代后端事实状态。

## 11. 个性化对话模块

### 11.1 定位

该模块将会话历史、长期记忆和模型能力组织成连续的个性化对话体验。

### 11.2 核心能力

- 创建、选择、重命名和删除会话。
- 保存用户消息和助手回复。
- 提供流式回复体验。
- 管理同一会话中的并发生成。
- 选择必要的近期历史。
- 调用检索模块获取相关长期记忆。
- 将已确认的用户画像注入系统提示词，实现个性化回复。
- 构造最小必要上下文。
- 记录模型调用结果和失败状态。
- 保存本次回复实际使用的记忆引用。
- 支持中止正在生成的回复。
- 支持重新生成失败或不满意的回复。
- 支持用户手动触发会话级提取，并以水位线标记已提取进度。

### 11.3 输入

- 用户消息。
- 当前会话历史。
- 检索出的长期记忆。
- 已确认的用户画像。
- 当前模型配置。
- 用户对记忆的确认状态。

### 11.4 输出

- 助手回复。
- 消息状态。
- 模型调用记录。
- 记忆引用。
- 用户触发的会话级提取任务。

### 11.5 设计边界

该模块不实现底层检索算法，不直接依赖具体模型供应商，也不允许记忆提取阻塞主回复。

---

## 12. 记忆管理模块

### 12.1 定位

该模块负责将对话或活动中的重要信息转化为可审查、可修订、可追溯的长期记忆。

### 12.2 记忆来源

记忆可以来自：

- 用户主动创建。
- 用户对话。
- 助手回复。
- 用户主动选择的活动记录。
- 未来接入的文件、日历或其他授权数据源。

首版不应默认将全部活动记录自动转化为记忆。

### 12.3 核心能力

- 从指定来源生成候选记忆。
- 校验候选记忆的内容、类型和重要性。
- 保存记忆与来源证据关系。
- 支持用户确认。
- 支持用户纠正。
- 支持用户否定。
- 支持用户删除。
- 支持查看记忆来源。
- 支持查看记忆修订历史。
- 支持记忆合并和去重。
- 在记忆变化时更新检索索引。
- 排除已否定和已删除的记忆。

### 12.4 记忆状态

| 状态 | 说明 |
|---|---|
| 候选 | 系统生成，尚未确认 |
| 已确认 | 用户确认可以长期使用 |
| 已纠正 | 用户修改后形成的新版本 |
| 已否定 | 用户明确认为不准确或不应使用 |
| 已删除 | 用户要求移除 |

### 12.5 设计边界

模型不能绕过程序校验和用户控制直接写入不可修改的长期事实。

---

## 13. 检索与上下文组装模块

### 13.1 定位

该模块从本地记忆和必要的历史记录中选择与当前问题最相关的信息，为对话和其他 AI 能力提供上下文。

### 13.2 核心能力

- 全文关键词检索（FTS5 BM25）。
- 向量语义检索（FastEmbed + ONNX 本地推理，默认模型 bge-small-zh-v1.5，512 维）。
- 混合检索融合排序：FTS5 候选（Top 20）与向量语义候选（Top 20）经 Reciprocal Rank Fusion（RRF）综合排序，结合时间新鲜度和重要性加权。
- 时间新鲜度计算。
- 记忆重要性计算。
- 用户确认状态过滤。
- 记忆来源和类型过滤。
- 结果去重。
- 上下文长度控制。
- 检索能力降级。
- 返回可追溯的检索来源。
- 检索索引状态查询（FTS5 全文索引 + 向量嵌入双通道状态）。

### 13.3 输出要求

检索结果需要包含：

- 记忆内容。
- 相关度（含 FTS5 BM25 得分和向量余弦相似度得分）。
- 记忆状态。
- 来源信息。
- 时间信息。
- 是否被最终上下文采用。

### 13.4 降级原则

当向量检索不可用时，系统应保留全文检索和基础对话能力。

当全部长期记忆检索不可用时，基础对话仍应可用，并明确提示个性化能力暂时受限。

### 13.5 设计边界

检索模块只选择候选上下文，不生成最终回复。

## 14. 桌面活动与隐私模块

### 14.1 定位

该模块在用户授权范围内记录基础桌面活动，并确保敏感场景在采集前被阻断。

### 14.2 首版采集范围

首版采集内容限定为：

- 应用名称。
- 窗口标题。
- 活动开始时间。
- 活动结束时间。
- 活动持续时长。
- 用户空闲状态。
- 采集来源平台。
- 隐私规则处理结果。

首版不默认采集：

- 原始键盘输入。
- 密码输入。
- 屏幕截图。
- 麦克风内容。
- 摄像头内容。
- 文件正文。
- 剪贴板历史。

### 14.3 核心能力

- 开启和暂停活动采集。
- 获取前台应用和活动时长。
- 获取空闲状态。
- 按规则判断是否允许采集。
- 阻断敏感应用和敏感窗口。
- 对允许记录的内容进行必要脱敏。
- 缓冲和批量提交活动事件。
- 处理重复事件和无效事件。
- 展示规则事实和运行时应用状态。
- 提供活动记录查询和删除入口。

### 14.4 隐私规则

隐私规则至少支持：

- 全局暂停。
- 应用黑名单。
- 应用白名单。
- 窗口标题关键字阻断。
- 特定时段暂停。
- 内容脱敏。
- 单次临时暂停。
- 平台级敏感场景强制阻断。
- **无配置时默认阻断**：未配置任何规则时默认阻断全部采集，不允许"先采后审"。

### 14.5 设计边界

活动记录属于原始事实，不直接等同于长期记忆或用户画像。

## 15. 用户画像与行为理解模块

### 15.1 定位

该模块从已确认记忆和时间窗口统计中形成可审查的用户理解。

### 15.2 画像类型

用户画像可以包括：

- 沟通偏好。
- 工作习惯。
- 学习偏好。
- 兴趣方向。
- 决策偏好。
- 时间习惯。
- 长期目标。
- 经常使用的工作模式。

行为模式可以包括：

- 活跃时段。
- 应用使用分布。
- 对话活跃度。
- 任务完成情况。
- 时间窗口变化趋势。

### 15.3 核心能力

- 从会话摘要与候选记忆中演化画像：新建（CREATE）、强化（REINFORCE）、修正（REVISE）。
- 保存画像与记忆之间的证据关系。
- 置信度随独立证据累积按程序规则递增，用户设定的置信度不被自动覆盖。
- 已确认画像的内容不被系统直接修改：内容冲突时生成候选修订版，由用户复核后替换旧版。
- 已否定画像禁止被自动重建（程序级兜底）。
- 支持用户确认、纠正和删除。
- 保存画像修订历史。
- 将已确认画像提供给对话模块作为个性化上下文。
- 统计时间窗口内的行为模式。
- 区分长期画像和短期行为。
- 防止未确认推断成为硬事实。

### 15.4 设计边界

画像是派生理解，不能替代原始记忆和活动记录。

## 16. 目标与任务模块

### 16.1 定位

该模块将 AI 理解和用户意图转化为可追踪的目标和任务。

### 16.2 核心能力

- 创建、修改和删除目标。
- 设置目标描述和目标日期。
- 管理目标状态。
- 创建、修改和删除任务。
- 将任务关联到目标。
- 支持独立任务。
- 管理任务优先级和状态。
- 展示目标进度。
- 从对话中生成任务建议。
- 要求用户确认后再创建 AI 建议任务。

### 16.3 首版边界

首版只管理本地目标和任务，不自动：

- 发送外部消息。
- 修改其他应用数据。
- 创建第三方日历事件。
- 操作文件。
- 执行系统命令。
- 将建议标记为已完成。

### 16.4 设计边界

AI 建议与已执行操作必须明确区分。

## 17. 模型与配置模块

### 17.1 定位

该模块隔离不同模型供应商和协议差异，为上层业务提供统一的模型能力。

### 17.2 核心能力

- 管理多个模型供应商。
- 管理对话模型。
- 管理结构化输出模型。
- 管理 Embedding 模型。
- 管理当前激活配置。
- 测试模型连接。
- 提供流式对话能力。
- 提供普通对话能力。
- 提供结构化输出能力。
- 提供向量生成能力（FastEmbed + ONNX Runtime 本地推理，默认模型 bge-small-zh-v1.5，512 维，完全本地离线运行）。
- 保存非敏感配置。
- 安全保存密钥。
- 对模型错误进行统一转换。
- 记录必要的模型调用信息。
- 控制向模型发送的上下文范围。

### 17.3 配置分类

配置分为：

- 模型供应商配置。
- 模型名称和能力配置。
- 服务地址配置。
- 超时和重试配置。
- 非敏感运行参数。
- 敏感密钥。
- 当前激活状态。

敏感密钥不得返回给前端页面，也不得以明文保存。

### 17.4 设计边界

模型供应商模块不决定业务提示词、记忆规则和用户状态。

## 18. 后台任务与调度模块

### 18.1 定位

该模块处理不应阻塞用户主流程的异步派生工作。

### 18.2 任务类型

- 会话级提取（会话分析生成摘要与候选记忆，随后执行画像演化）。
- 记忆向量更新。
- 用户画像刷新。
- 行为统计。
- 数据保留清理。
- 自动备份。
- 索引重建。
- 失败任务重试。

### 18.3 核心能力

- 创建任务。
- 保存任务状态。
- 防止重复任务。
- 领取和执行任务。
- 失败重试。
- 超时恢复。
- 任务取消。
- 任务结果记录。
- 任务积压统计。
- 任务最终状态收敛。

### 18.4 任务状态

| 状态 | 说明 |
|---|---|
| 待处理 | 已创建但尚未执行 |
| 执行中 | 已被工作进程领取 |
| 已完成 | 处理成功 |
| 待重试 | 失败后等待再次执行 |
| 已失败 | 超过重试上限或不可恢复 |
| 已取消 | 用户或系统取消 |

### 18.5 设计边界

后台任务不得出现“只创建、不消费、无最终状态”的中间状态。

## 19. 持久化与索引模块

### 19.1 定位

该模块作为系统本地事实源，为全部业务实体、证据关系和检索能力提供一致存储。

### 19.2 数据范围

- 会话和消息。
- 活动记录。
- 隐私规则。
- 长期记忆。
- 记忆来源。
- 记忆修订历史。
- 用户画像。
- 画像来源和修订历史。
- 目标和任务。
- 模型非敏感配置。
- 后台任务。
- 审计记录。
- 模型调用记录。
- 导出和备份记录。
- 全文与向量索引。

### 19.3 核心能力

- 事务管理。
- 外键关系。
- 数据迁移。
- 唯一约束。
- 级联删除。
- 全文索引（FTS5 虚拟表）。
- 向量索引（嵌入向量以 BLOB 存入记忆行，FastEmbed + ONNX 生成，NumPy 余弦相似度检索）。
- 数据文件加密。
- 数据一致性检查。
- 数据库健康状态。
- 索引重建。

### 19.4 事实与派生关系

- 用户修订后的画像。

以下数据属于可重建派生结构：

- 全文索引。
- 向量索引。
- 部分统计缓存。
- 搜索排序结果。

### 19.5 设计边界

索引故障不能被解释为“没有相关记忆”。

## 20. 数据治理模块

### 20.1 定位

该模块管理本地数据从产生、审查、保留到删除、导出、备份和恢复的完整生命周期。

### 20.2 核心能力

- 删除单条活动记录。
- 删除会话和消息。
- 删除记忆和画像。
- 删除目标任务。
- 处理关联证据和索引。
- 配置数据保留期限。
- 定时执行数据清理。
- 导出用户数据。
- 创建和管理备份。
- 执行受控数据库恢复。
- 清除全部本地数据。
- 记录不含敏感正文的审计信息。

### 20.3 删除原则

删除原始事实时，需要同步处理：

- 相关记忆来源。
- 派生画像。
- 对话引用。
- 全文索引。
- 向量索引。
- 行为统计。
- 其他关联数据。

不能只删除当前页面对应的一张表。

### 20.4 导出原则

用户导出应覆盖主要本地数据，并明确：

- 导出时间。
- 数据范围。
- 文件位置。
- 导出状态。
- 是否包含敏感内容。
- 是否加密。

### 20.5 恢复原则

数据库恢复期间需要暂停：

- 新对话写入。
- 活动采集。
- 后台任务。
- 索引写入。
- 自动清理和备份。

恢复失败时，应保留原数据库并提供回滚。

## 21. 审计与可观测性模块

### 21.1 定位

该模块用于说明系统当前是否可用、某项操作是否成功，以及错误发生在哪一层。

### 21.2 核心能力

- 聚合本地服务状态。
- 聚合数据库状态。
- 聚合全文索引状态。
- 聚合向量索引状态。
- 聚合模型配置状态。
- 聚合权限状态。
- 聚合后台任务积压。
- 记录关键设置变更。
- 记录数据删除和导出。
- 记录模型调用结果。
- 记录本地服务异常。
- 为用户提供可理解的错误提示。

### 21.3 状态展示原则

系统状态页面不得仅展示“已配置”或“未配置”，还应区分：

### 21.4 审计隐私原则

审计日志不得复制保存完整敏感正文。

## 22. 关键业务闭环

### 22.1 完成一次个性化对话

1. 用户选择或创建会话。
2. 用户输入消息。
3. 系统保存用户消息。
4. 检索模块查询相关长期记忆。
5. 系统将已确认画像与相关记忆组装为最小必要上下文。
6. 模型生成流式回复。
7. 页面持续展示回复。
8. 系统保存完整回复和引用关系。
9. 用户认为对话告一段落时，可手动触发会话级提取。

### 22.2 从对话形成长期记忆与画像

1. 用户在会话告一段落后手动触发提取，系统标记该会话的提取进度（水位线）。
2. 系统对水位线之后的新消息进行整体分析，生成会话摘要与候选记忆。
3. 程序校验记忆内容、类型与用户原文证据（助手回复仅作语境，不作为用户事实）。
4. 系统原子保存会话摘要与候选记忆及其来源。
5. 系统对比现有画像与新摘要、新记忆，执行画像演化（新建/强化/修正候选）。
6. 用户确认、纠正、否定或删除候选记忆与候选画像。
7. 有效记忆进入全文和向量索引；已确认画像进入对话上下文。
8. 后续对话可以检索该记忆并体现画像理解。

### 22.3 记录一次桌面活动

1. 用户开启活动采集。
2. 系统检查平台权限。
3. 系统获取当前前台应用。
4. 隐私规则判断当前场景是否允许记录。
5. 敏感场景被直接阻断。
6. 允许记录的活动被标准化和脱敏。
7. 活动记录写入本地数据库。
8. 用户可以在活动页面查看或删除记录。

### 22.4 将对话转成目标任务

1. 用户在对话中表达目标或行动意图。
2. AI 提供目标或任务建议。
3. 页面明确展示“建议”状态。
4. 用户确认后创建目标或任务。
5. 目标任务进入本地管理模块。
6. 用户更新执行状态。
7. 系统在后续对话中可以引用有效目标和任务。

### 22.5 删除一条原始记录

1. 用户选择活动、消息或记忆。
2. 页面展示影响范围。
3. 用户确认删除。
4. 数据治理模块定位关联证据和派生数据。
5. 系统执行一致性删除。
6. 全文和向量索引同步清理。
7. 系统记录不含正文的审计信息。
8. 页面重新查询并展示最终状态。

### 22.6 配置模型供应商

1. 用户填写非敏感模型配置和密钥。
2. 系统执行连接测试。
3. 用户确认保存。
4. 非敏感配置写入本地配置。
5. 密钥写入操作系统安全存储。
6. 本地服务重建对应模型能力。
7. 系统展示配置可用状态。
8. 后续对话和记忆处理使用当前激活配置。

## 23. 首版产品范围

### 23.1 首版必须完成

首版应形成以下可用闭环：

- Windows 和 macOS 可安装运行。
- Electron 能稳定启动和管理本地服务。
- 用户可以配置至少一种外部模型。
- 用户可以进行多会话流式对话。
- 系统能够从对话中生成候选记忆。
- 用户可以审查、确认、纠正、否定和删除记忆。
- 后续对话能够使用有效记忆。
- 用户可以查看基础桌面活动。
- 用户可以开启、暂停和配置隐私规则。
- 用户可以创建和管理目标任务。
- 用户可以导出、备份和删除本地数据。
- 系统可以展示关键能力状态和错误原因。

### 23.2 首版可降级能力

以下能力异常时，不应导致整个产品不可用：

| 异常能力 | 降级结果 |
|---|---|
| 向量检索不可用 | 使用全文检索 |
| 长期记忆检索不可用 | 保留基础对话 |
| 活动采集权限缺失 | 保留对话和手动记忆 |
| 画像任务失败 | 保留记忆和对话 |
| 自动备份失败 | 保留手动备份和业务使用 |
| 部分模型能力不可用 | 展示明确错误，不破坏本地数据 |

### 23.3 首版暂缓能力

以下能力暂不作为首版核心范围：

- 全局键盘文本采集。
- 屏幕持续截图。
- 麦克风和摄像头采集。
- 自动控制其他软件。
- 自动发送外部消息。
- 自动操作文件。
- 跨设备云同步。
- 团队协作。
- 复杂插件市场。
- 完全自主执行的桌面 Agent。
- 默认运行本地大模型。
- 高复杂度的自动日程和邮件代理。

## 25. 模块依赖关系

### 25.1 主要依赖

- 个性化对话依赖模型与配置、检索、持久化和安全通信。
- 记忆管理依赖模型与配置、后台任务、持久化和索引。
- 用户画像依赖会话提取产出（摘要与候选记忆）、后台任务和持久化，并向对话模块提供已确认画像。
- 活动采集依赖跨平台适配、隐私规则和持久化。
- 目标任务依赖持久化，并可被对话模块引用。
- 数据治理依赖全部数据生产模块和持久化。
- 前端页面依赖统一请求层和 Pinia，不直接依赖数据库。
- Electron 运行时依赖平台适配和本地服务，但不依赖具体业务页面。
- 索引依赖事实数据，事实数据不依赖索引。

### 25.2 禁止依赖

- Python 本地服务不得依赖 Vue 页面。
- 数据模型不得依赖 API 路由。
- 平台适配不得依赖记忆和画像业务。
- 前端组件不得直接读写 SQLite。
- Renderer 不得直接获得系统密钥。
- 页面不得直接持有本地服务随机端口和认证信息。
- 模型供应商实现不得直接修改业务状态。
- 向量索引不得成为记忆的唯一存储位置。

## 26. 统一状态与错误要求

### 26.1 前端状态

每个页面需要区分：

- 初始状态。
- 加载中。
- 加载成功。
- 空数据。
- 部分成功。
- 权限不足。
- 网络或本地服务错误。
- 业务错误。
- 系统错误。
- 正在重试。

一个下游步骤失败时，不得覆盖已经成功加载的其他数据。

### 26.2 错误分类

| 错误类型 | 产品处理 |
|---|---|
| 参数错误 | 在当前表单位置提示 |
| 权限错误 | 说明缺少的权限并提供操作入口 |
| 本地服务错误 | 提供重启或重试入口 |
| 模型连接错误 | 展示供应商和配置检查建议 |
| 业务错误 | 展示明确业务原因 |
| 数据库错误 | 阻止继续写入并保护现有数据 |
| 系统错误 | 展示通用提示并记录必要日志 |

### 26.3 部分成功

以下场景应允许部分成功：

- 规则列表加载成功，但桌面运行时同步失败。
- 对话成功，但记忆提取失败。
- 记忆保存成功，但向量索引更新失败。
- 数据加载成功，但行为统计失败。
- 备份创建成功，但旧备份清理失败。

系统应分别展示每一步的真实状态。

## 27. 验收原则

判断一个模块是否完成，不能只看是否存在文件、页面、接口或数据库表。

模块完成需要同时满足：

1. 存在用户可达入口。
2. 主业务流程可以端到端执行。
3. 成功状态可以持久化。
4. 失败状态可以被识别和展示。
5. 关键操作可以审计。
6. 权限不足时有明确降级。
7. Windows 和 macOS 的支持状态已说明。
8. 用户可以查看或控制与自己相关的数据。
9. 删除能够处理关联数据。
10. 页面遵守统一前端规范。
11. 模型输出经过程序校验。
12. 后台任务能够到达最终状态。

## 29. 开发参考原则

1. 页面只依赖统一请求层和桌面桥接能力。
2. 前端统一使用 Vue 3 Composition API 和 `<script setup>`。
3. 前端使用自定义组件和 Tailwind CSS v4，禁止使用 Element Plus。
4. 图标统一使用 FontAwesome 6。
5. 前后端协议使用 snake_case 和统一响应结构。
6. 路由页面统一懒加载。
7. Electron 只承担桌面生命周期、安全和系统适配。
8. Python 本地服务承担业务流程和模型编排。
9. 活动采集必须先通过平台权限和隐私阻断。
10. 模型输出一律视为候选。
11. 用户修订优先于自动推断。
12. 对外模型调用遵循最小必要上下文原则。
13. 删除事实数据时同步处理证据、派生数据和索引。
14. 后台任务必须具备创建、执行、重试和最终状态。
15. 跨平台差异通过统一能力状态表达。
16. 一个模块的失败不得无条件拖垮其他可独立运行模块。
17. 判断功能完成以用户入口和端到端闭环为准。
