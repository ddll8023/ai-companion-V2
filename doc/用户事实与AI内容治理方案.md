# 用户事实与 AI 内容治理方案

## 1. 背景与目标

AI Companion 同时保存用户消息和模型回复，以便维持连续对话。但“可用于理解用户的事实”与“模型生成的内容”不能混为一类：模型的复述、推断或建议若被当作用户事实，会污染长期记忆和用户画像。

本方案目标：

1. 保留完整、可继续对话的消息历史。
2. 只让具有用户证据的内容影响长期记忆和用户画像。
3. 保留用户认可的模型产出，使其可作为方案、知识或任务继续使用。
4. 让活跃度、摘要和画像分别使用正确的数据口径。

## 2. 核心定义

| 对象 | 内容 | 是否可直接影响画像 |
|---|---|---|
| 消息 `Message` | 用户、助手或系统的一次发言 | 否 |
| 对话轮次 `ConversationTurn` | 一条用户消息及对应的一条助手回复 | 否 |
| 用户事实记忆 `Memory` | 可追溯到用户原文的偏好、目标、习惯或事实 | 用户确认后可以 |
| AI 内容项 `AiArtifact` | 助手生成的方案、解释、清单、摘要或建议 | 否 |
| 已采纳 AI 内容 | 用户明确“记住”“采纳为目标/任务”后的 AI 内容 | 转为候选记忆后可以 |
| 会话摘要 `SessionSummary` | 对一段会话的压缩描述 | 否，仅用于会话浏览和上下文 |

## 3. 目标数据流

```text
用户消息 ──→ 本轮候选记忆 ──→ 用户确认 ──→ 长期记忆 ──→ 用户画像
                 │
                 └─ 证据必须能定位至用户消息原文

助手回复 ──→ AI 内容项 / 会话摘要
                 │
                 └─ 用户收藏、记住或采纳 ──→ 候选记忆 / 目标 / 任务

用户消息 + 助手回复 ──→ 会话上下文、会话摘要
```

## 4. 设计规则

### 4.1 消息与活跃度

- `messages` 继续保存 `user` 与 `assistant` 两种消息，这是对话历史的事实来源。
- 用户对话活跃度仅统计 `role = user` 且 `status = completed` 的消息。
- 后续若需展示“完成轮次”，按用户消息与其成功完成的助手回复配对统计，而不是直接统计消息行数。

### 4.2 轮次边界

- 发送用户消息时创建一个对话轮次，并关联该用户消息。
- 助手回复完成后，将回复消息关联到同一轮次。
- 候选记忆提取默认只处理该轮次，不能在每轮重复扫描最近 N 条消息。
- 跨轮归纳是独立的“会话摘要”任务，不能复用为长期记忆提取。

### 4.3 用户事实记忆

候选记忆的结构化输出必须新增并校验：

```json
{
  "content": "用户偏好简洁回答",
  "type": "preference",
  "importance": 6,
  "evidence": "请直接简洁地告诉我结论",
  "source_message_id": 123
}
```

- `source_message_id` 必须属于当前轮次且 `role = user`。
- `evidence` 必须是该用户消息中的原文片段；后端无法验证时丢弃该候选。
- 助手消息只能作为理解当前提问的上下文，不能作为用户事实的证据来源。
- 用户确认后，记忆才进入 FTS 和向量索引，并成为画像输入。

### 4.4 AI 内容与显式采纳

模型回复默认以 AI 内容保存，不能自动进入画像。对每条助手回复提供以下操作：

| 操作 | 结果 |
|---|---|
| 收藏 | 保存为 AI 内容项，供用户后续检索，不影响画像 |
| 记住这个方案 | 创建“待确认的 AI 建议”候选；用户确认后才转长期记忆 |
| 采纳为目标/任务 | 创建目标或任务草稿，用户确认后生效 |
| 不相关 | 可选反馈，不创建长期数据 |

“用户没有继续回复”不视为认可；只有显式操作或明确的后续用户表述才视为采纳。

### 4.5 用户画像

- 画像提取只读取状态为 `confirmed` 或 `corrected` 的用户事实记忆。
- 画像来源页必须展示对应记忆及其用户原文证据。
- 无有效用户证据的历史记忆不参与新的画像提取；可在数据迁移后标记为“待复核”。

## 5. 分阶段实施

### 阶段一：修正统计与事实边界

1. 活跃度只统计用户消息。
2. 记忆提取改为只处理本轮用户消息。
3. 在记忆提取结果中增加 `source_message_id` 和 `evidence`。
4. 后端实施用户原文证据校验。

状态：已实施。

### 阶段二：引入对话轮次与会话摘要

1. 新增 `conversation_turns` 表，关联用户消息和助手回复。
2. 新增 `session_summaries` 表，仅保存会话压缩信息。
3. 为长会话按轮次或时间窗口生成摘要，不写入长期记忆。

状态：已建立对话轮次与会话摘要数据模型；自动摘要调度将在会话摘要入口上线时启用。

### 阶段三：引入 AI 内容采纳流程

1. 新增 `ai_artifacts` 表，保存可收藏的模型方案、解释与清单。
2. 在助手消息气泡上提供收藏、记住、创建任务等操作。
3. 记录采纳关系和审计日志，确保可追溯与可撤销。

状态：已实施收藏、显式“记住方案”和“创建任务建议”入口；任务沿用既有待确认建议流程。

### 阶段四：历史数据治理

1. 为旧记忆补充来源类型与证据完整性状态。
2. 无用户原文来源的自动候选记忆标记为“待复核”，不自动删除。
3. 重新提取画像时只使用证据完整的已确认记忆。

## 6. 验收标准

1. 用户发送一次、助手成功回复一次时，用户对话活跃度增加 1。
2. 模型回复中未经用户确认的建议不会成为长期记忆或画像证据。
3. 每条自动候选记忆都可定位到一条用户消息及原文证据。
4. 用户收藏模型方案后，可以检索该方案，但画像不发生变化。
5. 用户明确“记住”并确认后，该内容才会进入长期记忆并可参与画像。
