## 2. 全局速查表

1. **模块函数风格**：Services 层使用模块函数，不写 `XxxService` 类
2. **统一响应格式**：所有接口返回 `{code, message, data}`，用 `success()` / `error()` 构造
3. **错误码用枚举**：`ErrorCode.XXX`，禁止硬编码数字
4. **日志**：统一使用 `logging.getLogger(__name__)`，禁止 `print()`
5. **文件路径操作**：统一使用 `os` 模块（`os.path.join` / `os.path.abspath` / `os.path.exists`），禁止 `pathlib.Path`
6. **Schema 转换**：用 `model_validate()` 和 `model_dump()`，不用已废弃的 `from_orm()`
7. **分层依赖**：API → Services → Models，API 不直接操作数据库
8. **命名空间包**：各层不使用 `__init__.py`，通过模块直接导入导出
9. **同名模块别名导入**：同一模块名跨层存在时使用 `层名_模块名` 别名（如 `services_task3`、`models_task3`）
10. **函数无返回值注解**：模块函数不使用 `-> XxxResponse` 返回值类型注解
11. **每函数一行 docstring**：描述函数做什么

## 4. 项目约定

### 4.1 项目结构

```
backend/
├── app/
│   ├── main.py            # FastAPI 应用入口
│   ├── core/
│   │   ├── config.py      # Settings（pydantic-settings）
│   │   └── database.py    # 引擎、会话管理、模型基类
│   ├── models/            # SQLAlchemy 数据模型
│   ├── schemas/           # Pydantic 请求/响应 Schema
│   ├── services/          # 业务逻辑（模块函数）
│   ├── api/               # FastAPI 路由
│   ├── tasks/             # 后台任务
│   └── utils/             # 工具函数
├── pyproject.toml
├── uv.lock
└── .env
```

### 4.2 数据目录

- 数据库文件存放于项目根目录下的 `data/` 目录
- 日志由 `logging` 模块管理，格式：`%(asctime)s %(levelname)s %(name)s: %(message)s`

### 4.3 通信协议

- 请求参数和请求体使用 `snake_case`
- 后端统一返回 `{code, message, data}` 三部分
- `code === 0` 表示业务成功

### 4.4 例外规则

- 仅存在于单一层的模块（如 `app.schemas.common`），无需别名，可直接导入。例如 `from app.schemas.common import ErrorCode` 是允许的。
